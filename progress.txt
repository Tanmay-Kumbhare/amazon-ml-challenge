2. KEY ARCHITECTURAL DECISIONS & CONSTRAINTS AGREED UPON
--------------------------------------------------------------------------------
[DECISION 1: OPEN-SET COUNTRY HANDLING]
- Observation: Training set has 'US' and 'India'. Test set introduces 'France'.
- Strategy: We DO NOT train ML models on Country as a feature (to avoid model panic on 'France'). Instead, Country is used strictly as a HARD BLOCKING RULE (only matching S1 records against S2/S3 records in the same country).

[DECISION 2: LEAKAGE-FREE LOCAL VALIDATION]
- Strategy: Hold out 20% of Source 1 entities in a group split. Validate strictly using F0.5 score locally before submitting to Amazon's test cases to preserve leaderboard rank.

[DECISION 3: MULTI-PARAMETER & GENTLE CLEANING]
- Strategy: Avoid over-cleaning addresses (keep numbers and unique tokens) so we don't accidentally merge different branches of franchises (e.g. McDonald's). Evaluate candidate pairs across all parameters (Name JW/Levenshtein/Jaccard + Address JW/Levenshtein/Jaccard + Blocking Score).

[DECISION 4: GPU ACCELERATION & MEMORY SAFETY]
- Strategy: Hardware features an RTX 3050 GPU (6GB VRAM) and 16GB RAM.
- Optimization: 
  1. TF-IDF + PyTorch CUDA GPU matrix multiplication for lightning-fast Top-K cosine similarity search.
  2. Batching/streaming candidate pair generation to prevent RAM OOM (Out Of Memory) errors.
